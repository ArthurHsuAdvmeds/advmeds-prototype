# tsghb-dashboard/real-data/20261103

三總北投精神健康個案通報管理儀表板的**真實資料版**。版面沿用 v7（已移除只屬於優化計畫／HIS 的頁面，只保留緊急醫療），
但畫面上的每個數字都由同資料夾的 `data.json` 即時計算，HTML 裡原型留下的數字只是佔位，載入完成前整頁隱藏。

程式集中在 `index.html` 檔尾的 `<script id="real-data">`（載入、正規化、日期篩選、各頁繪製）與 `<style id="real-data">`。
`normalizeCase()` 把 data.json 的一筆通報轉成畫面共用的案件物件，各頁的繪製函式只讀這個物件；
**data.json 的欄位改名或改代碼時，只需要改 `normalizeCase()` 與檔頭的代碼表**（`DEPARTMENT`、`SCALE_ROW`、`GENDER`、`ACCEPT_WAY`）。
熱點地圖仍在主腳本的地圖模組裡，透過 `window.RD.basicCases()` 取資料（`geoCases()`）。

> **repo 是公開的。** `data.json` 換成真實資料再 push，就會公開在 GitHub 與 Pages 上。
> 目前的 `data.json` 是使用者提供的 14 筆資料（原 `real_data.json`，通報日 2026/10/05–11/03，最外層只有 `updatedAt`，沒有 `sample`／`asOf`／`dataStart`），
> 由使用者自行 commit 推上（`726145f`，2026-11-04）；之後換資料要不要 push 由使用者決定。
> 先前的 420 筆虛構範例資料（最外層 `"sample": true`，頁首會標示「範例資料（虛構）」）留在 commit `b300075`。

## 1. data.json

單一 JSON 檔。允許 `//` 註解、區塊註解與結尾多餘的逗號（範本檔有註解）；最外層有 `"sample": true` 時頁首標示「範例資料」。

```jsonc
{
  "updatedAt": "2026-11-03",  // 選填：資料更新日，顯示在頁首「資料更新日」（可含時間，取臺北日期）；省略時頁首改顯示「資料截止」＋ asOf
  "asOf": "2026-11-03",       // 選填：本日／本月／本季／本年度以這天為「今天」，省略時取 updatedAt，再沒有就取最晚一筆通報的日期
  "dataStart": "2023-01-01",  // 選填：資料起日；指揮板預設區間、結案率的起始年度，省略時取最早一筆通報的日期
  "emg": [ { ... } ]          // 緊急醫療通報，一筆一個物件；其他鍵（之後的優化計畫）目前不讀
}
```

### emg 的每一筆

| 欄位 | 說明 | 畫面用途 |
| --- | --- | --- |
| `reportId` | 通報識別碼 | 地圖點位提示 |
| `reporterDepartment` | 通報者所屬網絡代碼，見下方對照 | 通報者頁 |
| `caseInfo.dict` | 行政區簡稱（`大安`；`大安區`、`臺北市大安區` 也可以） | 行政區長條圖、地圖 |
| `caseInfo.longitude`／`latitude` | 座標；同座標（小數 5 位）的通報合併成一個點位 | 地圖點位 |
| `caseInfo.gender` | `10` 男、`20` 女，其他算「不明」 | 性別 |
| `caseInfo.age` | 通報時年齡 | 年齡 |
| `assess.CTRS`／`GAF`／`BSRS5`／`CGIS` | `0` 低風險／輕度、`1` 中、`2` 高；空值不計 | 風險分析頁；**CTRS 同時當作「初評風險」** |
| `acceptWay` | `0` 電話、`1` 電話＋出勤 | 效率頁 |
| `timePoint.reportedAt` | 網絡完成通報時間。**所有日期篩選與時效指標的起點**；無法解析的筆數排除並列在頁首 | 全部 |
| `timePoint.assignedAt` | 完成指派醫師／護理師；未指派為 null | 待派／已派、派案時間 |
| `timePoint.acceptedAt` | 完成受理方式（＝處理完成時間）；未受理為 null | 效率頁 |
| `timePoint.outsideAt` | 實際出勤時間 | 出勤流程 |
| `status` | `0` 未結案、`1` 已結案、`2` 未開案／結案 | 各狀態件數、結案率 |
| `StatisfactionAvg` | 滿意度平均分 1–5；未填寫為 null（也接受拼法 `SatisfactionAvg`） | 通報者頁 |

**時間**：沒有時區的字串（`2026-11-03T08:50:36`）一律當臺北時間，日期篩選以臺北時間切日。

### 代碼與推導規則（★ 為待確認）

- ★ **`reporterDepartment` 對照**：data.json 只註明「0-7 為七大網絡、8 為其他」，沒有說各代碼是哪個網絡。
  目前 0–6 暫依 `db_desc` 的 `ref_network_unit` 順序：`0` 社政、`1` 警察、`2` 民政、`3` 衛政、`4` 教育、`5` 消防、`6` 勞政，`8` 其他；
  `7` 尚未對應，出現時列為「代碼 7（未對應）」並在頁首提示。確認後改 `DEPARTMENT`。
- **其他（8）** 固定列在通報者頁四張圖，排在七大網絡之後；代碼對不到或空值列為灰色的「代碼 N（未對應）」「未填」，排最後。
- **待派／已派**：`status = 0` 且 `assignedAt` 為 null＝待派，有值＝已派；`1`＝結案；`2`＝未轉介／開案（緊急醫療目前不會出現）。
- ★ **初評風險**取 `assess.CTRS`（風險檢傷評估）。效率頁總覽「不同風險個案處理時間」與地圖點位顏色、初評風險篩選都用它。
- ★ **縣市**：目前沒有縣市欄位。`dict` 對得到臺北市 12 區的算臺北市，其餘算「外縣市」，空值算「不詳」；地圖全臺層級因此只有臺北市有數字。
- ★ **滿意度**：問卷於結案時發出，所以「應回收」＝已結案（或已有分數）的案件，「已回收」＝`StatisfactionAvg` 有值；
  分數是各案件平均分再取平均。

## 2. 指標怎麼算

所有分頁都先依該頁的日期區間（`reportedAt` 的臺北日期，含頭尾）篩出案件；只有「結案率」不受日期篩選影響。

| 分頁 | 指標 | 算法 |
| --- | --- | --- |
| 基本資料 | 五張數值卡 | 案件數；待派／已派／結案／未轉介 依上方推導規則計數 |
| | 臺北市各行政區 | 臺北市 12 區（0 件也列出）由多到少；有外縣市、行政區空值的案件時多列「外縣市」「不詳」，總和＝總收案件數 |
| | 年齡 | 0-10 表示 0–9 歲…80+；空值另列「不詳」 |
| | 性別 | 男／女／不明（不明 > 0 才出現在圖例） |
| | 熱點地圖 | 縣市內各區件數＋初評風險組成；點位只畫有座標的案件，沒有座標的件數寫在圖例 |
| 風險分析 | 四種量表 | 該區間案件的 `assess` 各等級人次占比（三級合計 100%） |
| 效率：處置結果 | 結案率／電話處置率／出勤處置率 | 分母＝`acceptWay` 為 0 或 1 的案件；分子分別為已結案、0、1 |
| 效率：處理流程 | 各段平均（小時） | 電話流程用 `acceptWay = 0`、出勤流程用 `1` 的案件，**只取該流程每個時間點都有、且先後順序正確的案件**，所以各段平均相加＝總反應時間；樣本數在流程區塊的滑鼠提示 |
| 效率：總覽 | 高／中／低風險處理時間 | 依 CTRS 等級分組，`acceptedAt − reportedAt` 平均（小時），N＝兩個時間都有的案件數 |
| | 摘要卡 | 結案率、出勤總反應時間（同上） |
| 通報者 | 占比、轉介數量 | 依 `reporterDepartment` 計數 |
| | 回收率 | 已回收 ÷ 應回收（見上方滿意度規則） |
| | 滿意度分數 | 已回收案件的 `StatisfactionAvg` 平均 |
| 指揮板 | 各卡片 | 只有緊急醫療一類，左側總數＝緊急醫療列；預設區間為 `dataStart`～`asOf` |
| 結案率 | 各年度 | 依通報年度：已結案件數 ÷ 該年度通報件數，從 `dataStart` 的年度列到 `asOf` 的年度 |

時間差為負（資料錯誤）或缺任一端時不列入平均；沒有樣本時顯示「—」。

## 3. 開啟與驗證

- **file:// 直接開檔**：瀏覽器不允許網頁讀 JSON，頁首會出現「選擇 data.json」，選了就會載入（不上傳，只在瀏覽器內讀取）。
- **本機伺服器**：在 repo 根目錄跑 `python -m http.server`（本機用 `cd .tool && uv run python -I -m http.server 8765 --directory ..`），
  開 `http://127.0.0.1:8765/tsghb-dashboard/real-data/20261103/`。GitHub Pages 上直接可用。
- 換資料後檢查：頁首的資料更新日、總案件數，以及「已排除」「status 無法對應」「reporterDepartment 未對應」提示是否符合預期；console 不應有錯誤。
- 若要擴充回優化計畫：載入只讀 `emg`（`build()`），指揮板目前只有緊急醫療一列（`renderCommand()`），
  被移除的頁面與頁籤可以從 `../../v7/` 對照取回。
