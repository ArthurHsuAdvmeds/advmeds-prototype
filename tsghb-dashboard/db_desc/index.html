01設計重點

整個資料庫繞著「一筆通報」組織。先記住下面六件事，後面的資料表就容易對上。

  • 一筆通報一列，其他都掛在它底下

    pf_case 是中心。派案、各階段表單、量表、問卷都用 case_id 接回來；日期、類別、網絡這些篩選條件也都在這張表上。

  • 平台的表單一種一張表

    受理方式表單、出勤單、衛生局回覆單等各自成表，欄位只留指標用得到的。之後指標定義調整，改查詢就好，不必重新設計。

  • 時效指標先攤成里程碑

    mart_case_timeline 把每個案件各表單「最早的一筆」攤成一列。案件處理效率分頁的時效指標因此都是兩個時間欄位相減，比率指標都是依條件數件數。

  • 平台與 HIS 只在一個地方交會

    兩邊都把身分證字號換成同一種雜湊值 id_no_hash。比對結果彙總進 mart_case_his_outcome，17 個需要 HIS 的指標有 13 個讀它，另外 4 個純 HIS 指標讀 mart_snq_*。

  • 資料量小，不預先彙總

    一年幾百筆通報，各分頁的數字直接用 SQL 即時算，日期與類別怎麼篩都行。衍生表只做兩件事：取最早一筆、跨來源比對。

  • 不存可以認出人的資料

    沒有姓名、身分證明碼、電話和完整地址。地址只留行政區、座標與同址判斷用的雜湊值。

這份是依儀表板 v6 的畫面反推的需求。兩邊 API 實際給哪些欄位還沒核對過。第 3 節列出資料庫需要的欄位，請拿去對 API 文件；API 給不出來的欄位，對應的指標就算不出來，要回頭跟平台或 HIS 談。

HIS 要拉兩群人的就醫紀錄，查法不一樣：

  • 平台個案：以身分證字號查詢。結案日之後的門診、居家、住院紀錄是必要的；收案前一年的次數如果要改由 HIS 回溯，起點再往前推到通報日前一年。
  • SNQ 追蹤名單：初診為居家醫療的病人、強制住院後出院的病人，以及這兩群人之後的門診、居家、住院紀錄。這群人不一定是平台個案，所以 HIS 要能依條件列出名單，不能只靠身分證字號查。

04資料表

欄位定義以 pgsql.dbml 為準，這一節是同一份內容的閱讀版。點表名展開欄位。

慣例做法
表名前綴前綴就是來源：pf_ 平台、his_ HIS、ref_ 代碼與設定、mart_ 衍生、sync_ 同步紀錄。
字串一律 text，不用 varchar(n) 也不用資料庫 enum。代碼型欄位的允許值寫在欄位說明；需要顯示名稱或會增減的代碼才另開 ref_ 表。
主鍵與來源識別碼主鍵是 bigint 自動編號。來源系統的識別碼另存一欄 text 並設唯一，同步時靠它判斷新增或更新。
時間系統時間與表單上填的日期時間用 timestamptz，表單上只填日期的用 date。「本日、本月、本季、本年度」一律以 Asia/Taipei 切日。
衍生表mart_ 表不接受人工修改，隨時可以清空重建。要改成 materialized view 也可以，欄位照這裡的定義。

INSERT INTO mart_case_timeline (
  case_id, reported_at, assigned_at,
  em_intake_method, em_intake_at, em_dispatched_at,
  bureau_replied_at, bureau_visit_date, bureau_dispatch_date, bureau_decision,
  review_decision, review_completed_at,
  hosp_contact_at, hosp_replied_at, hosp_intake_result,
  first_assessment_visit_at, first_visit_at, handled_at, opened_at, closed_at)
SELECT c.case_id, c.reported_at, a.assigned_at,
       i.intake_method, i.completed_at, d.dispatched_at,
       b.completed_at, b.visit_date, b.dispatch_date,
       CASE WHEN b.decision = 'no_refer'                     THEN 'no_refer'
            WHEN b.decision = 'refer' AND b.referred_to_tsghb THEN 'refer_tsghb'
            WHEN b.decision = 'refer'                        THEN 'refer_other' END,
       r.decision, r.completed_at,
       h.contact_at, h.completed_at, h.intake_result,
       v.first_assessment_visit_at, v.first_visit_at,
       CASE WHEN g.category_group = 'emergency' THEN i.completed_at
            ELSE v.first_visit_at END,
       c.opened_at, c.closed_at
FROM   pf_case c
JOIN   ref_report_category g ON g.category_code = c.category_code
LEFT   JOIN LATERAL (SELECT min(assigned_at) AS assigned_at
                     FROM pf_assignment WHERE case_id = c.case_id) a ON true
LEFT   JOIN LATERAL (SELECT intake_method, completed_at
                     FROM pf_emergency_intake WHERE case_id = c.case_id
                     ORDER BY completed_at LIMIT 1) i ON true
LEFT   JOIN LATERAL (SELECT min(dispatched_at) AS dispatched_at
                     FROM pf_emergency_dispatch WHERE case_id = c.case_id) d ON true
LEFT   JOIN LATERAL (SELECT completed_at, visit_date, dispatch_date, decision, referred_to_tsghb
                     FROM pf_bureau_reply WHERE case_id = c.case_id AND completed_at IS NOT NULL
                     ORDER BY completed_at LIMIT 1) b ON true
LEFT   JOIN LATERAL (SELECT decision, completed_at
                     FROM pf_no_referral_review WHERE case_id = c.case_id
                     ORDER BY completed_at LIMIT 1) r ON true
LEFT   JOIN LATERAL (SELECT contact_at, completed_at, intake_result
                     FROM pf_hospital_reply WHERE case_id = c.case_id
                     ORDER BY completed_at NULLS LAST LIMIT 1) h ON true
LEFT   JOIN LATERAL (SELECT min(visit_started_at) AS first_visit_at,
                            min(visit_started_at) FILTER (WHERE visit_stage = 'assessment')
                              AS first_assessment_visit_at
                     FROM pf_visit WHERE case_id = c.case_id) v ON true
WHERE  NOT c.is_void;

SELECT count(*) FILTER (WHERE t.em_intake_method IS NOT NULL)                AS accepted_cases,
       round(100.0 * count(*) FILTER (WHERE t.em_intake_method IS NOT NULL
                                        AND t.closed_at IS NOT NULL)
             / nullif(count(*) FILTER (WHERE t.em_intake_method IS NOT NULL), 0), 1)  AS close_rate,
       round(100.0 * count(*) FILTER (WHERE t.em_intake_method = 'phone')
             / nullif(count(*) FILTER (WHERE t.em_intake_method IS NOT NULL), 0), 1)  AS phone_rate,
       round(100.0 * count(*) FILTER (WHERE t.em_intake_method = 'phone_dispatch')
             / nullif(count(*) FILTER (WHERE t.em_intake_method IS NOT NULL), 0), 1)  AS dispatch_rate,
       -- 時效：單位小時
       avg(extract(epoch FROM t.assigned_at      - t.reported_at)  / 3600) AS assign_hours,
       avg(extract(epoch FROM t.em_intake_at     - t.assigned_at)  / 3600) AS first_assess_hours,

         ORDER BY extract(epoch FROM t.em_dispatched_at - t.reported_at) / 3600) AS dispatch_total_p50,
       percentile_cont(0.9) WITHIN GROUP (
         ORDER BY extract(epoch FROM t.em_dispatched_at - t.reported_at) / 3600) AS dispatch_total_p90
FROM   mart_case_timeline t
JOIN   pf_case c ON c.case_id = t.case_id
WHERE  c.category_code = 'emergency'

量表改善情況四種量表、3 與 6 個月一次算完 
WITH pair AS (
  SELECT c.case_id, c.category_code, a0.scale_code, a1.timepoint,
         100 * CASE WHEN s.higher_is_better
                    THEN (a1.total_score - a0.total_score) / a0.total_score
                    ELSE (a0.total_score - a1.total_score) / a0.total_score
               END AS improve_pct
  FROM   pf_case c
  JOIN   pf_assessment a0 ON a0.case_id = c.case_id AND a0.timepoint = 'initial'
  JOIN   pf_assessment a1 ON a1.case_id = c.case_id AND a1.scale_code = a0.scale_code
                         AND a1.timepoint IN ('fu_3m', 'fu_6m')
  JOIN   ref_scale s      ON s.scale_code = a0.scale_code
  WHERE  NOT c.is_void
  AND    a0.total_score > 0 AND a1.total_score IS NOT NULL
  AND    c.reported_at >= :from AND c.reported_at < :to
)
SELECT scale_code, timepoint,
       count(*)                                              AS n,
       round(avg(improve_pct), 1)                            AS avg_improve_pct,
       count(*) FILTER (WHERE improve_pct >  1.0)            AS improved,
       count(*) FILTER (WHERE improve_pct BETWEEN -1.0 AND 1.0) AS flat,
       count(*) FILTER (WHERE improve_pct < -1.0)            AS worse
FROM   pair
GROUP  BY scale_code, timepoint;

JOIN   ref_report_category g       ON g.category_code = c.category_code
LEFT   JOIN mart_case_his_outcome o ON o.case_id = c.case_id
WHERE  NOT c.is_void
AND    c.reported_at >= :from AND c.reported_at < :to
GROUP  BY g.category_group;

       avg(extract(epoch FROM t.handled_at - t.reported_at) / 86400)

       avg(extract(epoch FROM t.handled_at - t.reported_at) / 86400)
         FILTER (WHERE c.initial_risk_level = 'medium') AS medium_days,

CROSS  JOIN LATERAL (SELECT (c.reported_at AT TIME ZONE 'Asia/Taipei')::date AS d) x

AND    extract(year FROM x.d) BETWEEN :year - 2 AND :year

07同步與重算

頻率是建議值，實際要看兩邊 API 的呼叫限制。

對象建議頻率做法
平台的案件與各表單每 10–15 分鐘增量；每天凌晨全量比對一次以來源的最後異動時間接續上次的 sync_run.window_end。畫面有「本日」篩選，所以白天要夠即時；凌晨的全量比對用來補漏和抓作廢案件。
HIS 的病人與就醫紀錄每天凌晨一次用 HIS 的指標都是結案之後的事，不需要當天即時。先同步平台，再拿已結案個案去查 HIS。
mart_case_timeline每次平台同步之後只重算這次有異動的案件；凌晨整張重建一次。
mart_case_his_outcome、mart_snq_*每天 HIS 同步之後整張清空重建。資料量小，重建比判斷哪些列要更新簡單，也不會留下過期的列。

一次同步的步驟

  1. 在 sync_run 開一列，記下來源、資源與這次要拉的異動區間。
  2. 呼叫 API。身分證字號在記憶體裡換成雜湊值，完整地址送去定位後只留座標與同址雜湊；去識別後的原始回應寫進 sync_raw_record。
  3. 以來源識別碼對 pf_* 或 his_* 做新增或更新（INSERT … ON CONFLICT … DO UPDATE），順手把平台的代碼轉成這裡的代碼。
  4. 重算受影響的 mart_*。
  5. 回頭把 sync_run 標成 success 或 failed。畫面上的「資料更新時間」取每個來源最後一次 success 的結束時間。

08個資

儀表板只需要統計數字，所以資料庫從一開始就不放可以認出人的欄位。

  • 不存的東西：個案與通報者的姓名、身分證明碼、電話、完整地址、問卷的文字建議、診斷與醫囑。
  • 身分證字號：同步程式用 HMAC-SHA-256 加上一把金鑰算出雜湊值，只把結果寫進 id_no_hash。平台與 HIS 兩邊用同一把金鑰，才比對得起來。金鑰放在同步程式的機密設定，不進資料庫也不進版控。不要用沒有金鑰的 SHA-256，身分證字號的組合有限，窮舉就能還原。
  • 地址：只留縣市、行政區、座標與 address_key。座標本身仍然指得到住家，熱點地圖如果會給院外的人看，回傳前先降低座標精度。
  • 原始回應：sync_raw_record.payload 寫入前先拿掉上面那些欄位，並且只保留 90 天。
  • 帳號：資料庫開兩個角色。同步程式可以寫入；儀表板後端只能讀，而且不需要讀 sync_raw_record。
  • 明細：成效頁的個案明細只回傳通報類別、改善率與改善類別，不回傳任何識別碼。
