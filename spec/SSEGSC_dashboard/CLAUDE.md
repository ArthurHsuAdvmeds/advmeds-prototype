# spec/SSEGSC_dashboard — 沙崙智慧健康照護站儀表板（復刻版）

復刻 <https://shalun-care.docloop.pro/>（2026-10-16 版），作為開「儀表板調整規格」給功能師時的現況基準。
畫面、互動與指標算法都照原站移植；只有資料改成虛構。之後依調整規格做的修改記在第 7 節。

- 1920／1440／390 寬的整頁尺寸與原站相同，逐像素比對只有資料造成的數字與迷你趨勢線不同。
- 原站是 Vite + React 19 + Recharts 2 打包的單檔（約 740 KB，已壓縮混淆）。這裡改成不需編譯的寫法：
  React 18 UMD + [htm](https://github.com/developit/htm)（樣板字串取代 JSX）+ Recharts 2.15 UMD，全部走 jsDelivr。
- 程式裡各區段標題後的「原站：xx」是原站打包檔裡的變數名，要回頭對照原站時用。

## 1. 檔案

| 檔案 | 內容 |

## 2. 畫面結構

1. **頁首資料提示**：資料檢核有錯→紅色（可展開明細）；截止日距瀏覽器今天 > 14 天→橘色「已 N 天未更新」。
2. **首頁單屏**（≥1181px 固定一個螢幕高）：頁首 logo、資料期間（近7日／近30日／今年，預設今年）、「系統正常」（固定文字）。
   左欄「01 健康服務觸及」「02 健康推播與提醒」、右欄「03 智慧健康設備使用」「04 健康風險分析」四張主題卡；
   中間照護站立體示意圖（滑過主題卡時對應引線亮起）與三顆捲動鈕；底部四步驟說明列。
   點主題卡→主題抽屜（左欄卡從左滑出、右欄卡從右滑出）。
3. **01 健康風險發現**：風險發現率卡（點擊→下鑽抽屜，列出風險者的年齡、性別分布）、健康風險 TOP 5（點任一列→同一個下鑽抽屜）、全部健康風險分布。
4. **02 健康改善追蹤**：回訪人數、回訪率、六項改善率，共 8 張 KPI 卡。
5. **03 服務體驗滿意度**：整體滿意度環圈、細項滿意度七項。
6. 頁尾。

## 3. 資料格式（原站 user.json）

```text
{ dataThrough: "YYYY-MM-DD",            // 資料截止日，所有「近 N 日」都從這天往前算
  users: [{
    id, gender: 男|女, age, visitorSource, visitDate,        // visitDate = 首次到站日
    line?:    { source, joinDate, bound },                   // 有加入 LINE 才有；bound = 完成會員綁定
    records?: [{ date, device, values?, aiAnalysis?, status?, eyeRisk? }],
                // device：bp inbody bmi spo2 temp fundus grip cog
                // fundus 沒有 values，改填 status（normal／watch／abnormal）與 eyeRisk
    pushes?:  [{ date, type, opened, reportViewed?, revisited? }],
    sat?:     { date, 七個滿意度維度: 1–5 }, nps?: 0–10,
    followUp?: true }],
  proRecords?: [...] }                   // 專業服務場次；原站有檢核與統計程式，但畫面沒有用到
```

允許值與各設備的量測項目見 `index.html` 第①段（`DEVICES`、`DEVICE_ITEMS`、`PUSH_TYPES`…），檢核規則見第②段。

## 4. 指標定義（依原站程式）

期間＝「截止日往前 N 天」到截止日；「今年」＝截止日當年 1/1 到截止日。只有期間可切換，
程式另支援性別、年齡層、LINE 來源、設備的篩選（`filter` 物件），畫面上沒有控制項。

**判定門檻**（每筆量測各自判定）

| 設備 | 需追蹤 watch | 異常 abnormal |
| --- | --- | --- |
| 血壓 | 收縮壓 ≥130 或舒張壓 ≥85 | 收縮壓 ≥140 或舒張壓 ≥90 |
| 身高體重 BMI | ≥24 | ≥27 |
| InBody | — | 體脂率 ≥27%（男）／≥35%（女），或內臟脂肪 ≥12，或骨骼肌 <25kg（男）／<18kg（女） |
| 血氧 | <96% | <94% |
| 體溫 | — | ≥37.5°C |
| 握力 | — | 左右手較大值 <28kg（男）／<18kg（女） |
| 認知 | 總體認知表現 <70 | <60 |
| AI 眼底 | 資料直接給 status | 同左 |

**首頁與主題抽屜**

| 指標 | 算法 |
| --- | --- |
| 累計使用人數 | 新增訪客人數 + 新增會員人數 |
| 新增訪客人數 | visitDate 在期間內的人 |
| 新增會員人數（原站：完成會員綁定） | 期間內加入 LINE 且 bound 的人 |
| 加入 LINE 人數 | 期間內加入 LINE 的人 |
| 新增使用人數趨勢 | 每天的新訪客數 + 當天加入 LINE 且綁定的人數 |
| 會員年齡／性別分布（原站：使用者年齡／性別分布） | 期間內有量測的人（不限會員；環圈中央顯示「服務人數」） |
| 累積推播次數（原站：累積健康推播次數） | 期間內推播筆數；推播觸及人數＝收到推播的不重複人數 |
| ~~異常提醒數、轉介推播次數~~ | 已移除。原站為類型「健康異常提醒」／「異常轉介」的推播筆數 |
| AI 關懷總人數（原站：AI 追管總人數） | 收到類型為「AI 關懷」推播的不重複人數（只看這個類型）。原站是收到健康異常提醒、異常轉介、再次量測提醒、健康追蹤提醒任一種的人數，下方附開啟比例說明，已移除 |
| 推播內容類型分布 | 五類與推播類型的對應見 `PUSH_CATEGORIES`：照護站預約、健康商城通知、AI 關懷各自只算同名類型；生理量測結果＝AI 健康報告；其他推播＝其餘所有類型（健康衛教、個人化健康建議、活動／健康促進、健康異常提醒、異常轉介、再次量測提醒、健康追蹤提醒）。照護站預約、健康商城通知、AI 關懷是 2026-10-17 新增的推播類型（原站分類見第 7 節） |
| 累積量測次數 | 期間內量測筆數；各設備使用量分布依筆數排序 |
| 健康風險評估人次 | 「AI 分析」的量測筆數：InBody、認知、眼底一律算，其餘設備看 aiAnalysis |
| 中／高風險人次（原站：異常風險人次）／高風險比例 | 上述筆數中 watch＋abnormal 的筆數（＝風險等級分布的中風險＋高風險）／abnormal 筆數 ÷ 評估人次 |
| 各健康風險類型分布 | 高血壓＝血壓 abnormal 筆數；BMI／體組成異常＝身高體重或 InBody abnormal 筆數；三種眼疾＝眼底 eyeRisk 筆數（這裡算全部量測，不限 AI 分析） |
| 卡片迷你趨勢 | 期間 ≤30 天逐日，「今年」按月加總 |
| 抽屜趨勢圖 | 預設近 30 日；可選區間不超過首頁選的期間；選「今年」改按月加總。「健康風險分析」沒有趨勢圖 |

**主頁面區段**

| 指標 | 算法 |
| --- | --- |
| 健康風險發現率 | 期間內有任一筆 abnormal 的人 ÷ 期間內有量測的人 |
| 九類健康風險 | 血壓、BMI（身高體重 ≥27，InBody 的 BMI ≥27 也算）、體脂、內臟脂肪、骨骼肌、握力、血氧、認知各看 abnormal；AI 眼底＝abnormal，或 watch 但不是「影像品質不足」。同一人可落在多類 |
| 下鑽抽屜 | 期間內有任一筆 abnormal 的人，依年齡層、性別分組 |
| ~~下鑽「風險類型」「後續照護狀態」~~ | 已移除。原站：風險類型＝九類風險人數；後續照護狀態＝風險者中期間內收到任何推播／followUp 為 true／期間內 2 天以上有量測 |
| 回訪人數／回訪率 | 期間內 2 天以上有量測的人／÷ 期間內有量測的人 |
| 六項改善率 | 期間內同一指標至少 2 天有量測（同日多筆取平均），第一天落在「改善門檻」的人為分母；最後一天往好的方向改善 ≥3%，或已不在改善門檻，就算改善。改善門檻：血壓 ≥130/85、BMI ≥24（身高體重或 InBody）、體脂率、內臟脂肪、骨骼肌同上表、握力只看右手 |
| 整體滿意度 | **寫死 4.7**（`OVERALL_SAT`），不是由問卷計算 |
| 有效回收／細項滿意度 | 有填問卷、且期間內有量測的人（不看填答日）；細項＝各維度平均，四捨五入到 0.1 |

## 5. 原站的已知問題（復刻版照樣保留，開規格時可一併處理）

- **字型沒載入**：原站把 Google Fonts 的 `@import` 寫在樣式中間，被瀏覽器忽略，實際用的是使用者電腦上的字型（數字的 Barlow Semi Condensed 沒有生效）。
- **整體滿意度寫死 4.7**，不會隨期間或資料變動。
- 「累計使用人數」「累積健康推播次數」（現為「累積推播次數」）「累積量測次數」標題寫累計／累積，實際是所選期間內的數字。
- 累計使用人數＝新訪客＋綁定，同一人到站又綁定會算兩次。
- 改善追蹤的副標寫「首次異常後最新量測正常人數 ÷ 首次量測異常人數」，但程式另外把「改善 ≥3%」也算改善；
  且血壓、BMI 的改善門檻（130/85、24）比風險判定（140/90、27）寬。
- 健康改善追蹤的 8 張卡片迷你趨勢線都是同一條（期間內每段時間的量測人數），與各卡指標無關。
- 體溫異常的人會算進健康風險發現率，但九類風險沒有體溫；反過來，InBody 只有 BMI ≥27 的人會進「BMI 過重／肥胖」，卻不算在風險發現人數裡。所以 TOP 5 的佔比分母不完全對應。
- 健康風險 TOP 5 點任何一列都打開同一個「全部風險者」下鑽，不會依點的類別篩選。
- 服務體驗滿意度用三欄格線（0.8 : 1.55 : 1），只放兩張卡，右側三分之一空白。
- 手機（390px 寬）有水平捲動：回訪人數、回訪率卡片的說明泡泡隱藏時仍佔 230px 寬，超出畫面右緣（整頁撐到約 467px）。
- 原站程式裡還有 AI 眼底、單一設備、chain 三種下鑽，以及專業服務場次（proRecords）、設備使用率的統計，畫面上都沒有入口；復刻版沒有移植這些用不到的程式。

## 6. 虛構資料（assets/mock-data.js）

- 固定亂數種子，每次開啟數字都一樣；資料截止日固定 `2026-10-16`（與原站擷取時相同）。
  2026-10-31 起頁首會依原站行為出現「已 N 天未更新」橘色提示；要消掉就改 `DATA_THROUGH`。
- 依原站資料的分布調整：6,753 位民眾，約 63% 有量測，約 44% 回訪過；性別、年齡、設備使用比例、各設備異常率、
  推播類型與開啟率、滿意度平均等都接近原站。「今年」首頁各數字在原站的 ±10% 內。
- 原站資料有兩段型態，產生器照樣模擬：截止日前 30 天以前每週約 300 位新訪客、每次到站量 3–4 項；
  最近 30 天每天只有 3–4 位新訪客、每次到站平均只量 1.2 項、加入 LINE 的人全部有綁定（`RECENT_*` 參數）。
  「近 30 日」的新訪客、LINE、量測次數、推播次數接近原站；原站這段的異常比例特別高（高風險比例約 18%），產生器沒有模擬，
  所以近 30 日的中／高風險人次會比原站少。
- 推播（2026-10-17 調整後）：第一次量測當天一定收到一則（AI 關懷 44%、AI 健康報告 36%，其餘為再次量測提醒、衛教等）；
  回訪前 0–3 天有 70% 收到照護站預約、回訪當天 40% 收到 AI 健康報告、10% 收到 AI 關懷；量測異常的當天另有健康異常提醒、異常轉介；
  加 LINE 的人約 26% 收到健康商城通知。總量約 8,500 則（原站 8,391），今年的五類約為照護站預約 19%、健康商城通知 11%、
  AI 關懷 24%、生理量測結果 28%、其他 18%（使用者已確認這組比例）。照護站預約、健康商城通知、AI 關懷三種類型原站沒有。
- 個人層級的數值全部是亂數產生，不含任何原站的實際紀錄；**不要把原站的 user.json 放進 repo**。
- 改了產生器要自己確認：頁首沒有出現紅色「資料有 N 個問題」（檢核程式會擋格式錯誤）。
