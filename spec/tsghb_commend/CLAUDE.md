## 2. 畫面與尺寸

照截圖量。截圖的頁面捲軸 7px、內容寬 1528；用 1528 寬比對過，各區塊位置與截圖差 0–2px，頁面總高也一樣（1132）。
基礎樣式是電腦版；≤1023px 篩選列改兩欄，≤600px 改單欄（截圖只有電腦版，平板與手機是原型自己排的）。

| 區塊 | 規格 |
| --- | --- |
| Header | 高 58、`--brand`（`#0CB9E4`）；院徽膠囊 140×40；右側白色圓形通知鈕 40＋漢堡選單 |
| 個案資料卡 | 頁面四周留 24、卡片圓角 6；頭像 48；姓名 20px 粗體；資訊兩欄（第一欄寬 242、列高 25）；右上「編輯基本資料」高 38；分隔線下三個狀態標籤（高 24、字 12px） |

## 3. 分頁

- 四個分頁：歷次通報紀錄、對話留言區、通報史及處遇歷程、**備註（新增）**。
- 網址 `#` 記住目前的分頁：`#reports`、`#chat`、`#history`、`#note`。沒有 `#` 或不認得的時候停在「通報史及處遇歷程」（截圖的狀態）。
  分享 `…/spec/tsghb_commend/#note` 會直接開在備註。
- 鍵盤：在分頁上按左右鍵切換（到底會繞回），`Home`／`End` 跳到第一個／最後一個。
- 「歷次通報紀錄」「對話留言區」不在範圍內，只顯示一行說明。
- ≤600px 分頁字改 13px、間距 12，375 寬放得下四個；更窄時分頁列可以左右滑，選到的分頁會自動捲進畫面（只捲分頁列、不動整頁）。

## 4. 備註分頁（新增，規則是原型自己定的）

- 上方「共 N 則備註」＋「新增」；下方表格：備註內容｜建立者｜最後更新時間｜編輯、移除。
- 新增／編輯用對話框（原生 `<dialog>`）：
  - 備註內容必填，去掉頭尾空白後不能是空的，否則紅框＋「請輸入備註內容」；最多 500 字，右下角顯示字數。
  - 新增的排在最上面，建立者是目前登入的人（`CURRENT_USER`），時間是當下。
  - 編輯只改內容與「最後更新時間」，不改建立者與順序。
  - 「×」、「取消」、點對話框外面、`Esc` 都會關閉；在文字框裡拖曳選字、放開時滑到外面不算點外面。
- 移除前跳確認對話框。
- 儲存、更新、移除後右下方提示「已新增備註」「已更新備註」「已移除備註」；焦點放回「新增」或該則的「編輯」。
- 資料存 `sessionStorage`（鍵 `tsghb-commend:notes`）：重新整理還在，關掉分頁就回到預設的兩則（`DEFAULT_NOTES`）。
- 全部移除後顯示「還沒有備註，按「新增」寫下第一則。」
- 備註內容一律用 `textContent` 放進表格，打 HTML 也只會當文字顯示；換行照原樣顯示。
- ≤600px 改成一則一張卡片：內容、建立者與時間、按鈕由上而下，不必左右滑才按得到編輯／移除。

## 5. 靜態、沒有動作的部分

Header 的通知與選單、「編輯基本資料」、通報史的篩選（下拉選得動但不會篩選）與「新增」、表頭「通報歷程種類」旁的編輯圖示、每一列的檢視／編輯／移除。

## 6. 待確認（給了正式規則就改掉）

- 備註要記哪些欄位（目前：內容、建立者、最後更新時間），要不要分類、附檔。
- 誰看得到、誰可以編輯／移除（目前任何人都能改任何一則），要不要留編輯紀錄。
- 字數上限（目前 500）。
- 截圖寬度下 Header 只有通知與選單；更寬的螢幕正式系統可能會出現主選單與使用者名稱，原型一律照截圖。
- 平板與手機版面（篩選改兩欄／單欄、通報史表格在框內左右滑、備註改卡片）是原型自己排的。

---

## 7. 修改須知

- 資料都在腳本開頭：`HISTORY`（通報史的列）、`DEFAULT_NOTES`（預設備註）、人名 `CASE_NAME`、`CURRENT_USER`。這個 repo 是公開的，只能放虛構資料；不要把參考截圖或截圖上的個資放進來。
- **`.tbl-box` 的 `position: relative` 不能拿掉**：表頭的 `.sr-only`（「操作」）是絕對定位，少了它會跑出捲動框，手機上整頁被撐寬、畫面縮小。
- 改完用瀏覽器開電腦（1528 寬）與手機（375）看，備註的新增、空白送出、編輯、移除走一遍，並檢查 console 無錯誤。
