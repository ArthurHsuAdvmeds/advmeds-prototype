# 三軍總醫院北投分院 — 精神醫療快速應變平台（快速通報頁面）原型

單頁靜態原型：頁面提供緊急醫療通報、第一類優化計畫通報、第二類優化計畫通報

整體操作流程以 `design/.flow` 為準（FlowScript 語法，可用 `flow-chart/` 開）：
選通報類型 → 登入 → 輸入身分證字號比對 → 查無此人就新增個案、既有個案則依目前的通報情況分流 → 進入填表畫面或通報提示頁。
設計稿的檔名直接對應 `.flow` 裡的節點文字。

## 2. 技術結構

與 `spec/nhri_ms` 相同：內容放在 `<x-dc>` 元素中，由 `dc-runtime.js` 解析後以 React 渲染。

```html
<head>
  <script>window.__resources = { "<CDN 網址>": "./assets/js/<本地檔>" };</script>
  <script src="./assets/js/dc-runtime.js"></script>
</head>
<body>
  <x-dc>
    <helmet><style>…設計 token、字型…</style></helmet>
    …版面，用 {{ 變數 }} 綁定…
  </x-dc>
  <script type="text/x-dc">
    class Component extends DCLogic { … }
  </script>
</body>
```

- **`window.__resources` 不可移除。** dc-runtime 靠這張表決定 React 從本地副本載入還是回頭連 unpkg。
- **`{{ 變數 }}`** 綁 `renderVals()` 回傳物件的鍵；`<sc-for list="{{ forms }}" as="form">` 內可以用 `{{ form.name }}`。
- **`sc-camel-on-click="{{ handler }}"`** 是事件綁定（`sc-camel-xxx-yyy` 會變成 React 的 `xxxYyy` 屬性）；`<sc-if>` / `<sc-for>` 是條件與迴圈。
- `style-hover="…"` 是 hover 狀態樣式。

寫樣板時容易踩到的地方（看 runtime 原始碼確認過）：

- `<x-dc>` 裡的原始 HTML 會**先被瀏覽器當一般 DOM 解析**，之後才換成 React 的輸出。
  所以 `<img src="{{ x }}">` 會真的去抓一個叫 `{{ x }}` 的檔案（console 出現 404）、`<input type="date" value="{{ x }}">` 會跳格式警告。
  這類屬性改寫成 `sc-camel-src`、`sc-camel-value`，原始 HTML 就沒有那個屬性，渲染時仍會變回 `src`／`value`。
- 布林屬性**不能只寫屬性名**：`disabled` 會被當成空字串（false）。要寫 `disabled="disabled"` 或綁 `{{ 布林值 }}`。
- 文字節點裡的 `{{ 字串 }}` 會包一層 `<span>`，不能直接放進 `<option>`。
  下拉選單的選項在 `renderVals()` 用 `React.createElement('option', …)` 產生陣列（`options()`），樣板寫 `<sc-raw-select>{{ cityOptions }}</sc-raw-select>`。
- `<select>` 在樣板裡要寫成 `<sc-raw-select>`；空白選項（`value=""`）的灰字靠 `required` ＋ CSS `select:invalid`。
- `<helmet><style>` 也會經過 runtime 的字串處理：` 小寫開頭駝峰字=` 會被改寫，data URI 裡**不要出現 `viewBox=`** 之類的屬性。

## 3. 流程與畫面

畫面由網址 `#` 決定，`parseHash()` 解析、`guard()` 檢查前置條件，不符合就用 `location.replace` 轉走。

| `.flow` 步驟 | 畫面 | 網址 | 進入條件（不符合時轉去） |
| --- | --- | --- | --- |
| W1–W2 選擇通報類型 | 入口頁 | `#/` | — |
| W3 登入 | 登入頁 | `#/login?type=…` | 已登入 →「開始通報」 |
| R1–R2 輸入並比對身分證字號 | 開始通報 | `#/check?type=…` | 未登入 → 登入頁 |
| R2a 輸入個案聯絡資料、建立個案 | 新增個案 | `#/create?type=…&id=…` | 字號已存在 → 依下表分流；字號格式不對 → 開始通報 |
| Y1／Z0／X2_2 個案已有進行中的通報 | 通報提示頁 | `#/notice?type=…&id=…` | 字號不存在 → 開始通報；依下表不該看提示頁 → 填寫表單 |
| R2a2／X1／Y3／Z2／Z3 填表 | 填寫表單 | `#/report?type=…&id=…`（接續進行中的那一筆時加 `&resume=1`） | 字號不存在 → 開始通報；依下表該看提示頁 → 通報提示頁 |

`type` 是 `emergency`／`plan1`／`plan2`，`id` 是身分證字號。入口頁三張卡片直接連到 `#/check?type=…`，未登入時由 `guard()` 帶去登入頁，登入後回到「開始通報」。

**既有個案的分流**（`.flow` 的 R2b1 以下）集中在 `entryFor(type, kase, user)`，比對送出與 `guard()` 都用它，所以手動改網址也繞不過去：

| 所選類型 | 個案目前的通報 | 去向 | 節點 |
| --- | --- | --- | --- |
| 緊急醫療 | 沒有緊醫通報中（有沒有優化計畫通報中都一樣） | 填寫表單，新的一筆 | X1 |
| 緊急醫療 | 緊醫通報中，通報者是自己 | 提示頁，按鈕「繼續填寫」「變更風險等級」「返回」 | Z0 |
| 緊急醫療 | 緊醫通報中，通報者是別人 | 提示頁，按鈕「處置中再通報」「返回」 | X2_2 |
| 優化計畫 | 優化計畫通報中，通報者是自己 | 填寫表單，接續那一筆（`resume=1`） | Z2 |
| 優化計畫 | 優化計畫通報中，通報者是別人 | 提示頁，只有「返回」 | Y1 |
| 優化計畫 | 沒有優化計畫通報中，但有緊醫通報中 | 提示頁，只有「返回」 | Y1 |
| 優化計畫 | 兩種都沒有 | 填寫表單，新的一筆 | Y3 |

- 「優化計畫通報中」**不分第一類、第二類**：個案有第一類通報中、這次選第二類，一樣算有；通報者是自己時回到那一筆第一類的填表頁。
- 「通報者是自己」＝那一筆通報的 `reporter` 等於登入的使用者。

### 3.1 入口頁

以 `design/landing_page.png` 為準。Header 加上 Hero（斜向漸層、白色大標、右側 `hero.png`）與三張通報卡片。

| class | 標題／說明 | `--lp-title` 標題色 | `--lp-accent` 按鈕色 |
| --- | --- | --- | --- |
| `.lp-card--emergency` | 緊急醫療通報／由警察、消防隊員、公衛護理師、社工進行通報 | `--red-500` | `--red-300` |
| `.lp-card--plan1` | 第一類優化計畫通報／網路轉介之疑似精神病個案 | `--teal-500` | `--teal-300` |
| `.lp-card--plan2` | 第二類優化計畫通報／疑似精神病人被護送就醫未住院者 | `--teal-700` | `--teal-500` |

- 手機／平板：卡片單欄（最寬 560px）、橫式，插圖在左（寬 36%）。
- 電腦（`min-width:1024px` 且 `min-height:600px`，設計稿 1440×1024）：整頁收在一個視窗高度內、不捲動；
  Header 92、Hero 300、卡片 348×400，都用 `clamp()`＋`vh` 寫成，視窗變矮時等比縮小。`--lp-img` 是插圖相對圖片區高度的比例。
- Hero 標題字級綁 `--lp-hero-h`；插圖靠右、寬度不夠時裁切，左緣用 `mask-image` 淡出。
- 手機設計稿的卡片內容（緊急通報／優化計劃通報／處置追蹤）是舊版，內容以電腦設計稿的三張為準，手機只取版面。

### 3.2 登入頁

沒有 Header。背景圖 `login-bg.jpg` 以 **1440×1024 原尺寸置中、向四周重複**（電腦與手機設計稿量出來是同一張圖、同一個比例），
上面依序是白色膠囊（院徽＋平台名稱）、「通報平台」、60% 白的登入卡片（寬 334、圓角 16）。
輸入框電腦 34px 高／14px 字，手機 38px 高／16px 字。

- **任何非空的帳號密碼都能登入**，一律登入成 `DEMO_USER`；「透過 LINE 登入」直接登入；「忘記密碼？」「記住我」沒有作用。
- 登入後 Header 右上在電腦顯示使用者名稱（下拉只有「登出」），手機維持漢堡按鈕（選單內有使用者名稱與「登出」）。未登入時漢堡選單只有「登入」。

### 3.3 開始通報

標題列固定藍色「開始通報」（**不隨通報類型變色**）。卡片寬 600：身分證號輸入框、「比對」，卡片外是「返回」（回入口頁）。
說明文字「請輸入需通報個案身分證字號」電腦在卡片上方、手機在卡片裡（兩個 `<p>` 用 CSS 切換）。手機（≤600px）底部有醫院淡色背景。

- 輸入時自動轉大寫、去空白；格式 `ID_RE`：1 個英文字母＋1 碼（A–D 或數字）＋8 碼數字，**不驗檢查碼**。
- 字號存在 → 填寫表單；不存在 → 新增個案。

### 3.4 新增個案

標題列固定藍色「新增個案」，內容欄寬 1056。欄位照設計稿，**本流程與設計稿不同的地方**：

- **身分證字號帶入上一步輸入的值、disabled**，不能改。
- **身分證字號與出生年月日旁的「不詳」勾選都拿掉。**

其他：必填只有姓名、性別；出生年月日用原生 `type="date"`；縣市／鄉鎮市區目前只有臺北市、新北市（`CITIES`），選了鄉鎮市區自動帶郵遞區號；
「上傳圖片」只做本機預覽。「送出」建立個案後進填寫表單，「取消／返回」回開始通報。
電腦版地址三欄並排、按鈕兩欄；手機全部直排。

### 3.5 填寫表單

**標題列文字與主題色、通報區塊標題依通報類型切換**，其餘（「未完成」標籤、「未填寫」按鈕、步驟圓圈）三種類型都是紅色系：

| 類型 | 標題列文字 | 標題列 `--qr-bar` | 區塊標題文字 | 區塊標題 `--qr-head` | 表單（＊必填） |
| --- | --- | --- | --- | --- | --- |
| `emergency` | 緊急醫療通報 | `--red-300` | 緊急醫療通報 | `--red-500` | 1 通報表＊、3 初評表 |
| `plan1` | 優化計畫通報 | `--teal-300` | 第一類優化計畫通報 | `--teal-500` | 1 優化計畫轉介單＊、2 衛生局回覆單＊（按鈕 disabled）、4 初評表、5 精神病患簡易篩檢表【家屬版】、6 精神病患簡易篩檢表【當事人版】 |
| `plan2` | 優化計畫通報 | `--teal-300` | 第二類優化計畫通報 | `--teal-500` | 同第一類 |

- 文字與表單清單在腳本的 `TYPES`，顏色在 CSS 的 `.qr-theme--*`（class 掛在最外層 `.lp-root`）。表單編號照設計稿寫死，不是流水號。
- 內容欄寬 1070：個案卡片（姓名、性別、身分證字號、生日與年齡、電話）＋通報區塊（通報編號、狀態、通報日＝今天、通報者＝登入者、表單清單）。
- **「未填寫」按鈕只是靜態畫面，沒有動作**（表單內容是既有功能，不在這份原型裡）。
- 「查看基本資料」展開個案的完整資料；「關閉」收合表單清單。這兩個是原型自己加的互動，方便確認資料有帶過來。
- **接續進行中的通報**（網址帶 `resume=1`：Z0 按「繼續填寫」進來的緊急醫療、Z2 的優化計畫）：
  通報編號、通報日、通報者顯示那一筆的，`filled` 裡的表單按鈕變成綠色「已填寫」（`.qr-btn--done`），也就是「填到一半」的樣子。
  「已填寫」的樣式沒有設計稿，是原型自己定的。新的一筆則是通報編號「-」、通報日今天、通報者是登入者、全部「未填寫」。

### 3.6 通報提示頁

以 Z0／X2_2 的電腦稿與 Y1 的手機稿為準，三種情況共用一個版面，由 `entryFor()` 回傳的 `mode` 決定差異：

| `mode` | 節點 | 插圖 | 按鈕 |
| --- | --- | --- | --- |
| `self` | Z0 | `notice-phone.png` | 「繼續填寫」（進填到一半的緊急醫療填表頁）、「變更風險等級」（**靜態，沒有動作**）、「返回」 |
| `other` | X2_2 | `notice-phone.png` | 「處置中再通報」（**靜態，沒有動作**）、「返回」 |
| `blocked` | Y1 | `notice-stop.png` | 只有「返回」 |

- 版面：橫幅高 160（左 `--teal-300` 到右 `--qr-alert-to` 的水平漸層、警告圖示、24px 標題）、插圖 280×280、
  資訊卡（通報編號、類別、通報日、通報者；類別文字是 `TYPES[…].short`）、按鈕。內容欄寬 568；「返回」回開始通報。
  電腦上 Z0 的兩個按鈕並排，手機直排。
- **橫幅標題**：那一筆通報的通報者是自己 →「該個案已被貴單位通報」，是別人 →「該個案已被其他單位通報」。
  這條規則是原型自己定的：同一張設計稿裡電腦與手機兩個畫面的標題不一致（三張稿合計出現「已被通報」「已被貴單位通報」「已被其他單位通報」三種），
  取其中與節點條件吻合的那兩種。使用者若給了正式規則，改 `renderVals()` 的 `noticeTitle`。
- 資訊卡用電腦稿的純文字樣式；Z0／X2_2 手機稿上帶圖示、紅字「緊急通報」的卡片是舊版，沒有採用。

## 4. 狀態與資料

`state`：

| 欄位 | 說明 |
| --- | --- |
| `route` | 目前畫面 `{ view, type, id, resume }`，由 `onHash()` 從網址算出；換畫面時表單與錯誤訊息一併清空 |
| `user` | 登入的使用者名稱，未登入為 `null` |
| `cases` | 以身分證字號為鍵的個案資料：`SEED_CASES` ＋這個分頁新建的 |
| `f` | 各畫面的表單值（登入、比對、新增個案共用一個物件，鍵對應欄位的 `name`） |
| `errors` | 驗證訊息：`login`、`check`、`name` |
| `menuOpen`／`infoOpen`／`formsOpen` | Header 選單、基本資料、表單清單的開合 |

- 登入狀態（`qr-user`）與新建的個案（`qr-cases`）存在 `sessionStorage`：重新整理還在，關掉分頁就清空。上傳的照片是 blob 網址，不存。

**`SEED_CASES` 是「身分證字號已存在」的示範個案**，其他字號一律視為不存在。資料全為虛構：

| 身分證字號 | 進行中的通報 | 通報者 | 選緊急醫療 | 選優化計畫 |
| --- | --- | --- | --- | --- |
| `A123456789` | 無 | — | 填表頁（X1） | 填表頁（Y3） |
| `B123456789` | 緊急醫療 | 自己 | 提示頁（Z0） | 提示頁（Y1） |
| `C123456789` | 緊急醫療 | 別人 | 提示頁（X2_2） | 提示頁（Y1） |
| `D123456789` | 第一類優化計畫 | 自己 | 填表頁（X1） | 接續那一筆的填表頁（Z2） |
| `E123456789` | 第一類優化計畫 | 別人 | 填表頁（X1） | 提示頁（Y1） |

- 進行中的通報掛在個案的 `emergency` 與 `plan`（`plan` 另有 `type`），欄位是 `no`（通報編號）、`date`、`reporter`、`filled`（已填寫的表單編號）。
  「自己」是 `DEMO_USER`、「別人」是 `OTHER_USER`。
- **進行中的通報只存在於 seed**：「未填寫」按鈕是靜態的，在原型裡新建個案或進填表頁都不會產生通報中的紀錄。
- **`account.csv` 是同一份清單給人看的版本**（登入方式＋各 seed 的情境，UTF-8 含 BOM 供 Excel 開啟）。
  它列在根目錄 `.gitignore`，只存在使用者本機，不要 `git add -f`。**改 `SEED_CASES` 時要同步改 `account.csv`。**

## 5. 版面樣式

集中在 `<helmet>` 最後一個 `<style>`：`lp-*` 是外框、Header 與入口頁，`qr-*` 是流程頁。基礎樣式是手機版，電腦版在兩個 media query：
`(min-width:1024px)` 管 Header 與流程頁，再加 `(min-height:600px)` 的那一塊只管入口頁的「一頁不捲動」。

- `.qr-wrap` 用 `--qr-col`（內容欄最大寬度）與 `--qr-gutter`（兩側最小留白）決定左右 padding，各畫面只改這兩個變數。
- 顏色用 `:root` 的設計 token；token 沒有的（頁面底色、Hero 漸層）定義在樣式開頭的 `--lp-*`。
- 尺寸都是從設計稿量出來的（電腦稿是 2 倍圖），改版面時對照 `design/` 裡的圖。

## 6. 修改須知

- 入口頁每張卡片的連結在插圖與「進行通報」按鈕各寫一次，改的時候兩處都要改。
- 入口頁電腦版要維持一頁不捲動：新增內容時請確認 1280×720 仍能完整顯示。
- 入口頁手機版卡片標題字級是 `clamp(16px,5.2vw,20px)`，為的是讓 9 個字的標題在 320px 寬仍排成一行。
- **六張暫用圖都是從設計稿處理出來的，拿到原圖後直接換檔：**
  - `notice-stop.png`、`notice-phone.png`：從 Y1 手機稿與 Z0 電腦稿裁下來（約 560×560，2 倍圖），設計稿的底色 `#fafafa` 已換成透明。
  - `hero.png`：從 `landing_page.png` 裁下來（680×298，漸層底一起裁進去）。原圖比例不同要改 `.lp-hero-art` 的 `aspect-ratio`，去背圖可以拿掉 `mask-image`。
  - `login-bg.jpg`：設計稿上背景被登入卡片與標題蓋住，這張是把電腦稿的 60% 白卡片反推回去、被輸入框與按鈕擋住的地方用手機稿同位置補上、
    剩下的小洞上下內插補出來的（2160×1536，顯示成 1440×1024）。紙飛機左翼尖端與視窗圖樣的頭像附近有很淡的補洞痕跡。
  - `hospital-bg.png`：從手機稿底部裁下來（563×488，1.5 倍圖），底色 `#f8f8f8` 一起裁進去，所以只在 ≤600px 顯示。
  - `report-forms.png`：從填表頁電腦稿裁下來（356×314，2 倍圖，白底）。
- 這個 repo 是公開的：`SEED_CASES`、`DEMO_USER` 只能放虛構資料；`design/` 裡的截圖也會被部署，放進去前確認沒有真實帳號或個資。
- 改完請用瀏覽器實際開啟，把流程走一遍：一個新字號走新增個案，五組 seed 各配三種通報類型共 15 種組合對照第 4 節的表，並檢查 console 無錯誤。
